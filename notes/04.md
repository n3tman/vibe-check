## Method (so lane 7 can redo or extend it)
Scripts lived in `cache/work/` (gitignored, not committed: outside this lane's files). Steps:
1. Blobless clone, then `git reset --hard` to fetch the HEAD tree in one batch (a path-form
   `git checkout HEAD -- .` fetches blob by blob and is far slower). Nothing from a repo was run.
2. `git grep -i -E 'msc ?[0-9]{3,4}' HEAD`, ignoring tests, changelogs, docs and CI for the
   evidence link. Per MSC the state is decided in this order (highest wins):
   - partial: Tuwunel's own compliance table says 🟨 (`docs/development/compliance/msc.md`);
   - experimental: Dendrite-family `mscs.mscs` list (`setup/mscs/mscs.go`), Synapse
     `unstable_features` entries gated on `config.*` (flag = that option, mapped to
     `experimental_features.*`), other config-file options named after the MSC;
   - unstable or stable: listed in the `/versions` `unstable_features` and on by default
     (stable if the MSC is merged into the spec); Synapse options whose default is `True`
     (e.g. `msc3575_enabled`, simplified sliding sync) count as unstable, on by default;
   - Tuwunel ✅ rows (note says "project self-assessment"); Tuwunel ❌ rows drop weak hits;
   - any other code reference: stable if the MSC is merged, else unstable (note says
     "referenced in code, no flag found; extent not checked"). This is the weakest level.
   `Cargo.toml` hits are ruma feature flags (`unstable-mscNNNN`): the server builds the ruma
   support, which is good but not proof of wiring.
3. `spec_versions`: the versions list in each server's `/versions` handler (file pinned).
4. MSC status: GitHub search API over all issues and PRs of matrix-org/matrix-spec-proposals
   (GraphQL and the per-issue REST endpoint are blocked in this session), labels mapped to
   merged | fcp | open | closed | postponed. Proposals that passed FCP and were merged into the
   proposals repo but whose spec PR is missing are `fcp` with `status_detail: accepted, spec PR
   missing` (MSC4186, MSC4143, MSC1767 …). `spec_version` = first spec changelog (v1.1 to v1.19)
   citing the MSC; a mention in a clarification can make it early for a few old MSCs (e.g.
   MSC1219 shows v1.1). Three pre-2019 proposals (MSC1236, 1301, 1812) are not returned by the
   search API: 1812 is filled from its proposal file, 1236 and 1301 from Tuwunel's MSC inventory,
   each with a `status_detail` saying so (the site's validator needs a title and a status).
5. `oidc_delegation`, `native_sliding_sync`, `media_auth` are derived from the MSC list
   (3861 family / 4186 / 3916); when the code cites no number but the server advertises the
   spec version the MSC landed in, the value is `yes` with an "implied" note.
6. AI: agent files in the tree, commits of the last 365 days (bots dropped) with AI trailers,
   AI bot authors, AI workflows; CONTRIBUTING / PR template / README / docs grepped for AI words;
   GitHub issue search for LLM / AI-generated / ChatGPT / "AI policy" on the five main GitHub repos.
