## Findings worth showing
- **bridgev2 migration**: on bridgev2 now: whatsapp, signal, telegram (rewritten from Python to
  Go; v26.10 dropped migration from the Python bridge), meta, gmessages, slack, twitter (also
  rewritten from Python), linkedin, gvoice, bluesky, irc, zulip, twilio, and third-party
  bridges (beeper/line, groupme, tumblr-dms, reddit, chatgpt-dots, matrix-steam-bridge,
  matrix-tiktok). Not yet: mautrix-discord (legacy bridge on `main`, rewrite on the
  `megadiscord` branch, active in Nov 2026), mautrix-imessage (legacy, one commit this year),
  mautrix-googlechat (still Python). matrix.org's listing still says Python for telegram and
  twitter.
- **AI policy**: one shared policy covers every mautrix project (docs repo
  `bridges/general/contributing.md`, "Use of AI", added 2026): AI allowed for code, author
  accountable, no AI for issues/PR text/comments → `restricted`. Out Of Your Element's README
  has an "AI policy" section ("100% organically cultivated ethical hand-fed code") → recorded
  as `banned` (our reading; flagged in the file's notes). matrix-steam-bridge discloses
  AI-assisted code in its README → `allowed`. The matrix.org bridges share
  matrix-appservice-bridge's CONTRIBUTING.md, which has no AI section.
- **AI dev usage**: attributed Claude co-author trailers appear in most active mautrix repos
  in Sep to Nov 2026 (one contributor, below 2 % except gvoice at 5.6 %), and heavily in
  Beeper's newer bridges (groupme ~50 %, line ~10 % plus CLAUDE.md/AGENTS.md, reddit ~26 %,
  chatgpt-dots ~10 %). matrix-tiktok has CLAUDE.md, AGENTS.md and .cursorrules but no
  attributed commits (`config-only`). Arona has copilot-swe-agent[bot] commits.
- **AI in product**: beeper/chatgpt-dots (bridges an OpenAI assistant, `core`), beeper/ai-bridge
  (archived, AI models as contacts, `core`), Arona (OpenAI-compatible module, `optional`).
- **ToS warnings**: only mautrix-telegram (account ban warning in its auth docs) and
  matrix-tiktok (legal disclaimer on reverse engineering) carry one; beeper/line warns that its
  session displaces the official Chrome extension. Everything else is `not-found`: no warning
  is not the same as no risk.

## Open questions and schema gaps
- Below-1 % attributed shares are shown as `occasional` (the rubric has no bucket between
  `none-found` and 1 %). Lane 7 may want a rule for that.
- `framework` is a feature map with `value: yes`; a plain enum field (`mautrix-bridgev2`,
  `mautrix-legacy`, `matrix-appservice-bridge`, `own`, …) would sort and filter better.
- No field for "bridged network" as a list; `network` is free text here.
- No field for a bridge's **successor** (mautrix-facebook → mautrix-meta, …); it is in notes.
- Licences: where the LICENSE file is GNU (A)GPL v3 without an -only/-or-later marker, the
  deprecated SPDX ids `AGPL-3.0` / `GPL-3.0` are used. matrix.org says GPL-3.0 for Postmoogle,
  the repo is AGPL.
- Maturity is matrix.org's label when listed, except where the repo contradicts it (archived
  repos → `archived`; matrix-appservice-discord, inactive since 2023 → `unmaintained`); unlisted
  projects use our reading of the commit history.
- Hosted-only bridges (`repos: []`) not covered.
