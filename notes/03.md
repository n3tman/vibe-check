## How the files were made
- Blobless clones in `cache/repos/`, nothing run. Each file pins sources to the HEAD commit read.
- Features with `how: code` and a note `pattern match [...]` come from a grep over the source
  tree (tests, docs, translations and vendored code skipped), taking the first matching file:
  for example `m.thread` for threads, `im.ponies`/ImagePack for custom emoji, `m.read.private`
  for private receipts. They show the client handles the event type, not that the feature is
  complete; treat them as "code mentions it". Features hand-checked from READMEs say `claimed`.
  Everything not seen is `not-found`, never `no`.
- AI dev usage counts: commits of the last 365 days with AI co-author trailers or "Generated
  with" lines, bots excluded. For forks that merge upstream (SchildiChat Next and Revenge, Sable
  v1, Rooster, Vommet) the count uses `--first-parent` so upstream's commits are not credited to
  the fork; the collector should do the same, or forks will show Element's or Commet's numbers.
- AI findings worth showing: Tesseract (86 % of commits Claude-attributed; README says it was
  written with Claude; Flathub refused it under its AI policy), Zam (81 %), Zooid (75 %), mnotify
  (49 of 50), Vommet (says most code is LLM-written), Rooster (23 %, CLAUDE.md), Relay (10 %).
  Policies: Sable v2 and Sailtrix ban AI-generated contributions; SchildiChat Revenge and Rooster
  ask for disclosure/understanding (restricted); Vommet is openly LLM-assisted (allowed).
  AI in the product: MindRoom Chat and Zooid (clients built for AI agents), both `core`.
- matrix.crafty.moe is the hosted copy of **Zam**. Its "uses AI" is AI-assisted development
  (81 % of last-year commits carry Claude trailers); no AI feature in the product and no written
  statement about AI found in the repo; the site itself is the app with no readable text.

## Trixnity Messenger (added after the first pass)
Tammy and Tacit get most of their features from trixnity-messenger
(https://gitlab.com/connect2x/trixnity-messenger/trixnity-messenger, AGPL-3.0, cloned to
`cache/repos/trixnity-messenger`). Each file is read at the version the client pins: Tammy at
4.11.0-SNAPSHOT (CI build of 2026-10-21, main commit f4b45841df), Tacit at tag v4.10.3. Found in
the main sources: OIDC, E2EE (vodozemac), cross-signing, recovery key, spaces, reactions, edits,
replies, location, voice messages, push, private receipts, presence, room upgrades, reporting,
multi-account, German and English UI; MatrixRTC calls only in the 4.11 snapshot (Tammy). Not found:
threads, polls, stickers, image packs, URL previews, sliding sync, 1:1 VoIP. trixnity-messenger
has no agent files, no AI-attributed commits (2,009 in the last year) and no AI policy text.
The Trixnity SDK under it (https://gitlab.com/trixnity/trixnity) was not checked; sliding sync
would live there. Trixnity Messenger itself is an SDK, for lane 8 if it runs.
