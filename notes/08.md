## Method
- Blobless clones in `cache/repos/<slug>/` of all 76 reachable repos; `git log` for activity and
  AI trailers, counted with the collector's own `vibecheck.ai` and `vibecheck.authors` functions
  (non-bot commits of the last 365 days; the collector recounts). Nothing from a clone was run.
- For 27 active SDKs a working tree (`git reset --hard` on the blobless clone, no hooks, no
  filters) was grepped for MSC4186 / MSC3575, MSC2965/MSC3861 / `auth_metadata`, `m.thread`,
  `m.space.child` / hierarchy, vodozemac / libolm / matrix-sdk-crypto, MSC4108, MatrixRTC and
  appservice code; each feature value links the file (pinned to the commit read) and says what was
  found. Inactive or tiny libraries get `not-found` with the note "not checked" for features.
- AI policy: CONTRIBUTING, PR templates, README, AGENTS/CLAUDE files read for AI, LLM, Copilot,
  ChatGPT, Claude, generated. Forge issue and discussion searches were **not** done (GitHub API not
  reachable from this session).
- The YAML files are generated by a script in the session scratchpad (records plus the scan); it is
  not committed. Edit the YAML directly from now on.

## Extra fields (not in docs/schema.md yet)
- `features.crypto`: bare string naming the E2EE implementation (vodozemac, libolm, goolm,
  matrix-sdk-crypto, "via matrix-nio", …). Bare because the site schema checks feature maps with a
  string `value` against yes/partial/no unless the key is in `FREE_TEXT`; the source is on `e2ee`.
- `features.used_by`: bare list of slugs. Computed from every other file's `sdk` / `framework`
  value and note (regex per SDK), plus SDK-to-SDK dependencies read in manifests (vodozemac ←
  matrix-rust-sdk, matrix-dart-sdk, Trixnity, matrix-nio, libkazv; matrix-sdk-crypto-wasm ←
  matrix-js-sdk; …). Lane 7: if `sdk` fields change, rerun the matching or check by hand. A client
  that names two SDKs (SchildiChat: js-sdk and android-sdk2) appears under both.
- `features.qr_login` (MSC4108), `features.matrixrtc`, `features.appservice`: yes/no features on a
  few SDKs.
- `features.purpose`: matrix.org's purpose list (client, bot, bridge) or ours (crypto, widget,
  server).

## Findings worth showing
- **E2EE crypto by SDK**: vodozemac directly (matrix-rust-sdk, matrix-dart-sdk, Trixnity or libolm,
  matrix-nio since its switch to the vodozemac bindings, libkazv); via matrix-sdk-crypto (matrix-js-sdk
  through crypto-wasm, matrix-bot-sdk through crypto-nodejs, libQuotient's Rust crypto-sdk, matrix-ios-sdk,
  matrix-android-sdk2, Matrix.swift); still libolm (mtxclient, mautrix-python, libcmatrix, mautrix-go by
  default with its own pure-Go goolm behind a build tag; Pickle uses goolm). libolm itself says "IMPORTANT:
  libolm is now deprecated."
- **Sliding sync (MSC4186)**: matrix-rust-sdk (native), matrix-js-sdk (simplified_msc3575 prefix),
  Ruma (types); none found in the Dart SDK, Trixnity, libQuotient, mtxclient, mautrix, nio.
- **Next-gen auth (OAuth / MSC3861)**: rust-sdk, js-sdk, Trixnity ("OAuth2-based login"), mautrix-go
  (OAuth helpers), Ruma (types); partial in the Dart SDK ("considered as beta"), matrix-ios-sdk and
  matrix-android-sdk2 (metadata only).
- **AI policies**: Ruma `banned` ("Contributions must not include content generated by large language
  models …"); matrix-rust-sdk `restricted` (disclosure, no AI-written communication, no AI review, no
  agent mode); matrix-js-sdk `restricted` (PR template disclosure checkbox; AI-generated PR descriptions
  get the PR closed); Element's fork of matrix-bot-sdk `restricted` via Element's org-wide policy. All
  others `none-found`.
- **AI dev usage** (attributed commits, last 365 days): matrix-dart-sdk 13 of 475 (2.7 %, 11 of them
  authored by cursoragent@cursor.com; its AGENTS.md has Cursor Cloud instructions and tells the agent
  to commit as cursoragent with no Co-authored-by trailer), mautrix-go 7 of 700, matrix-js-sdk 5 of 364,
  matrix-client-api (syncpoint) 3 of 118, matrix-rust-sdk 2 of 2,822, libkazv 1 of 37 (opencode),
  matrix-sdk-crypto-nodejs 1 of 169, Pickle 1 of 109. All `occasional` (matrix-rust-sdk's
  policy requires disclosure, which a co-author trailer is one form of).
- **In product**: only Pickle mentions AI ("Streaming AI responses", an AI SDK adapter), recorded as
  `optional`; it is plumbing for AI bots, not an AI feature of the SDK.
