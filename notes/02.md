Method: blobless clones in `cache/repos/` for history (AI trailers over the last 365 days, authors),
shallow `--depth 1` clones in `cache/src/` for greps of the code (MSC prefixes, SDK calls,
analytics SDKs). Nothing from any clone was run. Feature values marked `claimed` mostly come from
the matrix.org listing or the README; `code` from a grep, pinned to the commit read. Many features
of the small or dead clients are left `not-found` rather than guessed.

## Decisions worth knowing
- **matrix-axon** (PLAN category check): Axon is a self-hosted always-on Matrix client (a bouncer)
  that ships its own TUI, web, desktop and mobile clients. Filed as a client, slug `axon`.
- **matrix.crafty.moe** (PLAN: "says it uses AI") is **Zam**: its web manifest says name "Zam",
  id `moe.crafty.matrix`; matrix.org lists it as `zam`. Slug z, lane 3.
- **Komai** is listed by PLAN under bots and tools but is a chat client (matrix.org lists it), so
  lane 2 wrote `komai.yaml`. Lane 5 should not write a second one.
- **Element**: three product files (`element-web` with Desktop, `element-x` with Android and
  iOS, `element-classic` with the old Android and iOS apps) plus `element-call` and
  `element-nextcloud` (a Nextcloud packaging by a third party). Element Desktop moved into the
  element-web monorepo (`apps/desktop`); the old element-desktop repo is listed as a second repo.
- **Element AI policy**: element-meta's CONTRIBUTING.md (2026-11-02) applies "to all Element
  projects: the repositories of element-hq, and the matrix-org repositories where Element is the
  core contributor" and accepts AI-assisted contributions with disclosure in the PR template and
  full author accountability: `restricted`. Used for element-web, element-x, element-classic,
  element-call and hydrogen.
- **FluffyChat** changed its policy on 2026-10-22: the LLM ban (from 2026-06-01) and an AGENTS.md
  that forbade agents to edit files were removed, replaced by "We do not vibe code!". Set to
  `restricted`; the history is in the file's notes.
- **Fractal** has an AGENTS.md whose content is a refusal aimed at agents. It is not evidence of
  AI use; `dev_usage` stays `none-found`. The collector's config-only rule will flag it: lane 7
  may want an exception list.
- **Lightning**'s CLAUDE.md says the history was rewritten on 2026-08-11 to strip AI co-author
  trailers, so the collector will count 0 % attributed commits. The file says `regular` from the
  project's own statement.
- **Forks** set: cinny-ir (Cinny), extera (FluffyChat), komai (`nheko`, lane 3's slug), jorvik
  (heorot), element-nextcloud (element-web, packaging). Heorot and Jorvik say they derive parts
  from Element Web without being forks of it.
- Maturity: matrix.org's label when listed ("Obsolete" mapped to `unmaintained`), our reading
  otherwise (said in each file's notes).

## Open questions and things the schema lacks
- `dev_usage` has no value for "attributed commits under 1 %" (FluffyChat 0.1 %, gomuks 0.3 %).
  I used `occasional`; the rubric could say "any attributed commit, under 5 %".
- No field for policy history or date: FluffyChat banned then relaxed within five months. A
  `policy.since` date and `policy.history` list would show it.
- No field for an organisation-wide policy that a repo inherits (`policy.scope: org`).
- `apps[].note` is used in a few files (not in the schema): free text about the app.
- `in_product` for on-device ML that is not generative (Element Call's MediaPipe background blur):
  recorded as `none-found` with a note. The methodology page could say where the line is.
- Store pages were not fetched (Google Play, App Store, F-Droid), so `min_os` comes from the code
  (minSdk, deployment target) where found, else null.
- Not done for lack of time: issue and discussion searches on non-GitHub forges, and the AI-policy
  check of kazv's contributing page (https://kazv.chat/en/contributing/).
- The YAML files were generated from compact records by a script in the session scratchpad (not
  committed); edit the YAML directly from now on.
