# Lane 10: project icons

Checked 2026-11-05. 162 of 345 projects now have their own icon in `site/public/icons/`
(1.2 MB in total, every file under 64 KB); the other 183 keep the generated monogram. The first
pass covered the 270 projects then in `data/`; the second pass (below) added the 75 SDKs and
looked again at the 130 without an icon.

## How the icons were found
1. **Repo file (99 icons).** A shallow blobless clone of every repo in `cache/` (`--depth 1
   --filter=blob:none --no-checkout`), the HEAD tree listed and scored by path: Fastlane
   `metadata/android/*/images/icon.png`, AppStream `hicolor/scalable/apps/*.svg` and 256/512 px
   PNGs, iOS/macOS `AppIcon.appiconset` 1024 px, Android `mipmap-xxxhdpi/ic_launcher`, then
   `logo*` / `icon*` / `<project name>*` files and `favicon.svg`. Files under `vendor/`, tests,
   emoji, screenshots, bridge/network folders and the like were skipped; a file named after
   anything other than the project or a generic word (logo, icon, app, …) was ignored, so a
   bridge's `telegram.svg` never matched. Only blobs were read (`git show HEAD:<path>`); nothing
   from a repo was run. A candidate had to be a real image, square-ish (aspect ≤ 1.35 for
   rasters, ≤ 1.6 for SVG) and at least 120 px.
2. **Homepage (10 icons).** For projects with no repo hit, the homepage's
   `<link rel="icon">` / `apple-touch-icon` (one page request and one icon request per host,
   forge pages skipped).
3. **Forge avatar (31 icons).** GitLab / Forgejo project avatars (the project's own picture),
   then the owner's avatar only when the owner is an organisation. GitHub's user API and
   `github.com/<owner>.png` are blocked in this session, so organisation type and avatar URL
   came from the search API (`search/users?q=user:<owner>`) and the image from
   `avatars.githubusercontent.com`. Generated identicons were filtered out.

Every pick was then reviewed by eye on contact sheets (each icon on light and dark).

## Processing
- SVG: parsed and sanitised (no `script`, `foreignObject`, animation, event handlers, external
  `href`s or `url()`s, foreign namespaces, DOCTYPE or entities); `@media (prefers-color-scheme)`
  blocks removed, because an `<img>` follows the OS scheme rather than the site's switch;
  `width`/`height` dropped, `viewBox` kept or derived. Kept as SVG when ≤ 64 KB, otherwise
  rendered (Chromium, every network request blocked) and treated as a raster.
- Raster: padded to a transparent square, 128 × 128 WebP (lossless when it fits in 64 KB),
  no metadata.
- `icon.backing`: computed from the rendered icon (≥ 20 % transparent and mean luminance
  < 0.22 → `light`, > 0.85 → `dark`), then corrected by hand for gotktrix, seaglass, barkvr
  (none needed) and SmallTalk (`dark`, a white foreground layer). `.picon-on-light` gets a
  light tile in the dark theme, `.picon-on-dark` a dark tile in both.
- `icon.licence` is the project's own `licence` for repo files; `null` for homepage icons and
  avatars, where no licence is stated.

## Site changes outside `site/public/icons/` (for the integration lane)
- `site/src/lib/schema.ts`: optional `icon` object; `site/src/lib/data.ts`: the validator
  fails when `icon.file` is missing, misnamed, or when an icon file has no `icon` key.
- `site/src/components/ProjectIcon.astro`: reads `icon.backing`; `site/src/styles/global.css`:
  `.picon-on-light` / `.picon-on-dark`, and `a.repo-link` for the repo table.
- `site/src/components/Icon.astro`: forge marks `forge-github`, `forge-gitlab`,
  `forge-forgejo` (also Codeberg), `forge-gitea`, `forge-sourcehut`, `forge-other`, drawn for
  this site; `site/src/pages/p/[slug].astro` shows them on the repo links and the repository
  table, with the forge name as the accessible label.
- `site/src/pages/methodology.astro`: one sentence on logos as trademarks under "Sources and
  dates". `docs/schema.md`: the `icon` key.
- Not changed: `site/scripts/screenshots.mjs` serves `.webp`/`.png` as
  `application/octet-stream`; Chromium still renders them, but adding the two types would be
  tidier.
